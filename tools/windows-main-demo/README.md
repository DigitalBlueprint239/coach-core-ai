# Existing main app on local emulators

Operational setup only. Application source0dc94c4 (main accepted code unchanged), using the existing emulator build recipe with import OFF and fake demo config. No A0 sidebar extension, AI, cloud upload, production auth or deployment. The main app and A0 remain separate. Launcher and Windows setup are operator helpers, not a new product release/acceptance claim.

Runtime: Node22+ and Java21+, plus network to install the pinned Firebase CLI/functions packages and download Google's emulator JARs on first run. No Firebase login, billing or real project. The launcher strips cloud credentials/proxy values from its child environment only, selects demo-coach-core-e2e explicitly, and binds every service to127.0.0.1. AI and Film params are OFF; secrets use a non-key placeholder.

`node start.cjs` verifies the package hashes, installs pinned emulator-tools/functions dependencies if absent, starts Auth/Firestore/Functions/Storage emulators, and opens http://localhost:3000/start. That local route uses only Auth-emulator owner APIs to grant beta to synthetic `.test` accounts and complete emulator email-link sign-in through the existing app SDK. It is not a production auth bypass or live beta grant. No passwords or real account are required. The main static server denies external network destinations via CSP; real Google sign-in is unavailable intentionally. Use the local start address to sign in.

Ctrl+C attempts a local emulator export into `.local-state` before stopping. The next start imports that synthetic state. A failed export is reported and data may not survive restart; do not treat emulators as backup/storage for real information. User device setup and local restart/export must be observed before claiming them verified. Windows can require approval for local software installation; do not disable firewall or change security policy to make this run.

The local setup seeds the existing server-owned users document for each synthetic account and waits for the existing createUserProfile trigger before opening it; this is emulator account provisioning, not a change to app behavior. Child CLI configuration is isolated under .cli-config so cached Firebase logins are not used. CI mode disables CLI MOTD/remote-config polling; no live Firebase project is selected. The optional emulator admin UI is disabled to avoid an unnecessary download; the app has one start address.

Observed main-app visual defect: this unchanged CRA build retains literal Tailwind directives and has no generated .w-6 or .fixed utility rules. Some controls render unstyled and success-toast icons are oversized. The six targeted real-browser persistence tests pass despite that defect; UI polish/complete visual acceptance is not claimed. The setup does not patch accepted app CSS. Initial operator UI-download and shutdown/export issues were corrected before delivery; their logs are retained.

Windows use: download the ZIP, choose Extract All, open the extracted folder and double-click START-COACH-CORE.cmd. Keep its console open. The launcher automatically opens http://localhost:3000/start after readiness. Node22 is confirmed on Coach Drew's PC. Java21+ and native-Windows startup are not yet confirmed remotely. If Java is missing, install the free Eclipse Temurin21 JDK, then reopen the starter. No Firebase login or real email is needed.
