# Private security reporting

Do not open public issues or PR comments containing credentials, tokens, exploit details, identifiable coach/player records, youth media or unredacted browser/auth traces. Do not paste secrets into any report, including private reports; identify the credential type and location without its value.

Claude Code owns independent security review; Coach Drew is the accountable human contact. Use the repository's **Report a vulnerability** private flow if available, or your established private channel with Coach Drew to arrange a restricted handoff to Claude. Private vulnerability reporting availability and the private contact channel have **not been verified** in Phase A. If neither is available, stop public disclosure and request a private channel from Coach Drew without including the sensitive finding. No email address or enabled reporting feature is inferred here.

Public coordination on #39 should contain only a redacted tracking identifier, owner and blocker status. Raw evidence stays in access-controlled storage agreed with the reviewer; publish only sanitized summaries and checksums. Emulator tokens are also redacted. Repository and Actions artifacts may be public: they are not private security storage.

No automated remediation, secret rotation, production access, deployment or deletion is authorized by this policy.
