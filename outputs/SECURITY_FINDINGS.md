## Secrets audit scope

Scanned current tracked/materialized text for key-shaped Google, OpenAI and GitHub credentials and private-key headers, without printing values. Main candidate path: `.env.local.example`, a commented reference value. Standalone: zero matches across 84 retrieved files. No confirmed model credential, token or private key found in this limited scan. This is not proof of absence: entropy scanning, complete Git history, remote CI secrets and deployed bundles/configuration were not audited. The excluded Windows-incompatible Python file was not included in the local text scan.

The concrete risk is build-time secret injection if keys are later supplied. Firebase public project configuration is not interchangeable with a privileged model/Admin key. Secret validity was not tested against provider APIs. No credential was printed in reports, committed, or supplied to browser code. Evidence logs are sanitized for known credential-shaped strings.

## Authentication, persistence and configuration limits

Main Firestore tests globally mock Firebase SDK. Their passing results prove service control flow, not enforcement. `firebase.json` declares emulator ports but application emulator connectors are commented out. Java and Firebase rule compilation were not available; real access rules, login providers, authorized domains, indexes, App Check and IAM remain unverified.

`addToOfflineQueue` is present once, pushes an operation, and saves. Retry behavior resides in syncOfflineQueue: failures requeue except permission-denied message matches. It is not malformed or duplicated, but replay is not a secure, crash-safe transaction: queue is cleared before async writes, logout partitioning is absent, and create with docId uses updateDoc. No retry logic was changed.

Main local play serialization stores saved plays; undo/redo are separate state arrays. Standalone saves the present playbook, not past/future; isolated storage test verifies that boundary. Neither browser-local workflow establishes private team isolation on a shared device. Real youth roster/contact data should not be introduced until access and data retention are tested.

Main already has a top-level ErrorBoundary; it catches the auth mismatch in mocked tests. Standalone emits browser React errors (`Layer` incorrect casing and non-boolean `listening`) and install export shows an error alert. No crash-free mobile or full export workflow was established.

## Security release gates

Before private beta: no secret-bearing client AI path; single authenticated identity; valid rules that compile and deny foreign tenants; protected destructive functions; reproducible compatible dependencies and advisory disposition; safe account-scoped storage/offline behavior; complete coaching workflow verification. Test against a demo/emulator project without modifying existing Firebase data. Live configuration review and any public/paid deployment require a separate approved step.
